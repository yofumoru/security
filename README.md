# Учебный стенд Java, WireGuard и OAuth 2.0

Веб-приложение и учебный сервер OAuth 2.0 используют встроенный HTTP-сервер JDK 17. WireGuard работает в двух экземплярах sing-box. В Windows стенд проверен с HiddifyCli 4.1.0 (hiddify-sing-box 1.13.1) без установки сетевого драйвера.

## Запуск на одном компьютере

### Сборка и конфигурация

Команды выполняются из корня проекта с помощью JDK 17. При наличии нескольких версий Java используются `java` и `javac` из каталога JDK 17.

```powershell
javac -encoding UTF-8 -d build src/Lab.java src/LabConfig.java
java -cp build LabConfig
```

`LabConfig` запускается один раз и создаёт VPN-профили `.lab/server.json` и `.lab/client.json`, а также файл `.lab/credentials.txt`. Первая строка `credentials.txt` содержит пароль пользователя `student`, вторая — секрет OAuth-клиента. Каталог `.lab` исключён из Git.

### Сервисы

Каждый сервис работает в отдельном терминале. Готовность определяется по сообщениям о запуске в консоли.

**Веб-приложение и OAuth-сервер**

```powershell
java -cp build Lab
```

**VPN-сервер**

```powershell
& 'C:/Program Files/Hiddify/HiddifyCli.exe' --disable-color srun -c .lab/server.json
```

**VPN-клиент**

```powershell
& 'C:/Program Files/Hiddify/HiddifyCli.exe' --disable-color srun -c .lab/client.json
```

Для стандартного sing-box с поддержкой WireGuard и пользовательского стека сети команда имеет вид `sing-box run -c .lab/server.json` или `sing-box run -c .lab/client.json`.

## Вход и проверка доступа

Главная страница доступна по адресу [http://127.0.0.1:18080/](http://127.0.0.1:18080/). Страница «Заметки» находится по маршруту `/notes`, личный кабинет — по маршруту `/private`.

Вход в личный кабинет начинается по ссылке «Войти через OAuth 2.0». Для авторизации используется учётная запись `student`. Следующая команда выводит только пароль:

```powershell
Get-Content -LiteralPath .lab/credentials.txt -TotalCount 1
```

После выхода личный кабинет снова требует авторизации. Для проверки VPN достаточно остановить клиентский процесс с `client.json` через Ctrl+C и обновить главную страницу. При запущенных Java и VPN-сервере браузер должен получить отказ в соединении.

## Конфликт порта 18080

Сообщение `bind: Only one usage of each socket address` при запуске VPN-клиента означает, что порт 18080 занят. PID процесса указан в последнем столбце вывода команды:

```powershell
netstat.exe -ano -p TCP | Select-String '127\.0\.0\.1:18080\s+.*LISTENING'
```

Если порт занимает VPN-клиент стенда и главная страница доступна, второй экземпляр не требуется. Повторный запуск возможен после завершения первого экземпляра.

## Размещение на двух машинах

1. При первой генерации профилей `LabConfig` принимает доступный с клиента IPv4-адрес или DNS-имя сервера. Например, `java -cp build LabConfig 192.168.56.10`. В существующем профиле адрес хранится в поле `endpoints[0].peers[0].address` файла `.lab/client.json`.
2. Приложение Java и VPN-сервер работают на серверной машине. Для подключения требуется входящий доступ от клиента по UDP 51820. Для клиентского хоста подходит сеть Host-only, для клиентской ВМ — общий виртуальный сегмент.
3. На клиентскую машину переносится только `client.json`. VPN-клиент использует этот профиль, а приложение открывается в браузере по адресу `http://127.0.0.1:18080/`. HTTP-порты 28080 и 28081 привязаны к loopback сервера.
4. Доступ проверяется по одному URL при работающем и остановленном VPN-клиенте. Для входа используется выданный учебный пароль. Секрет OAuth-клиента и закрытый ключ сервера хранятся на сервере.

Тестовая конфигурация использует локальные HTTP-адреса и хранит сессии в памяти. При переносе в эксплуатационную среду понадобятся HTTPS, безопасное хранение секретов и полноценный провайдер идентификации.
